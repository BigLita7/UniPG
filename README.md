# UniPG — спорт рядом в MAX

UniPG — Mini App и чат-бот для платформы MAX, предназначенные для поиска
спортивных площадок и организации совместных игр и тренировок.

Проект разработан для трека «Досуг и развлечения» по направлению
«Спорт рядом: секции, площадки и тренировки».

## Рабочая версия

- Mini App: [https://unipg.ru](https://unipg.ru)
- MAX-бот: `@t126_hakaton_max_bot`

## 1. Назначение

UniPG позволяет пользователю:

- находить спортивные площадки на интерактивной карте;
- фильтровать площадки по виду спорта;
- создавать спортивные события;
- присоединяться к существующим событиям;
- просматривать свои события;
- получать в MAX подтверждения создания, записи и отказа от участия;
- получать напоминание примерно за час до начала события;
- открывать событие на карте прямо из уведомления и отменять запись;
- переходить в связанный чат участников, если организатор добавил ссылку;
- запускать Mini App непосредственно из чат-бота MAX.

Для отображения карты и получения информации о спортивных объектах используется 2ГИС.

## 2. Основной пользовательский сценарий

1. Пользователь открывает бота UniPG в MAX.
2. Запускает бота командой `/start`.
3. Бот показывает меню с кнопками:
    - «Открыть UniPG»;
    - «Найти игру»;
    - «Площадки»;
    - «Мои события»;
    - «О проекте».
4. Кнопка `openApp` запускает Mini App UniPG внутри MAX.
5. Пользователь выбирает спортивную площадку на карте.
6. На площадке можно посмотреть существующие события или создать новое.
7. Пользователь может присоединиться к событию и позднее отказаться от участия.
8. Backend отправляет через MAX Bot API подтверждение записи и кнопку для
   возвращения к событию на карте.
9. За час до начала текущие участники получают однократное напоминание.
10. После отказа от участия пользователь и организатор получают уведомления.

## 3. Архитектура

Проект состоит из четырёх основных частей.

### Mini App

Интерфейс приложения, который открывается внутри MAX. В нём пользователь работает
с картой, ищет площадки, создаёт события, записывается на них и отменяет запись.

Для карты используются сервисы 2ГИС, а для взаимодействия с MAX — WebApp Bridge.

Исходный код: `mini_app/frontend/`.

### Backend

Серверная часть приложения на Python и FastAPI. Backend:

- получает информацию о площадках из 2ГИС;
- хранит спортивные события и список участников;
- обрабатывает создание события, запись и отказ от участия;
- отправляет уведомления пользователям в MAX;
- отправляет напоминание примерно за час до начала события;
- предоставляет Mini App REST API.

Исходный код: `mini_app/backend/`.

### MAX-бот

Чат-бот на Node.js. Он обрабатывает команды `/start` и `/help`, показывает меню
и открывает нужный раздел Mini App с помощью кнопок.

Исходный код: `bot/`.

### База данных

Для хранения событий, участников, профилей, чатов, информации об аренде и
отправленных напоминаний используется SQLite.

### Взаимодействие компонентов

1. Пользователь открывает Mini App через MAX-бота.
2. Mini App отправляет запросы в backend.
3. Backend получает площадки из 2ГИС и сохраняет события в SQLite.
4. При создании события, записи или отказе backend отправляет уведомление в MAX.
5. Перед началом события backend отправляет участникам однократное напоминание.

## 4. Локальный запуск через Docker

Перед первым запуском создайте файл `.env` на основе примера и заполните
необходимые ключи:

```bash
cp .env.example .env
```

Для запуска всех локальных компонентов выполните одну команду из корня проекта:

```bash
docker compose up --build
```

После запуска Mini App и REST API доступны по адресу
[http://localhost:8000](http://localhost:8000).

Локальный запуск позволяет проверить интерфейс и REST API. Для полного сценария
с уведомлениями и запуском Mini App внутри MAX используется рабочая версия,
указанная в начале README.

## 5. Необходимые параметры окружения

Для полноценной работы UniPG необходимы:

- токен MAX-бота;
- публичное имя MAX-бота;
- ключ 2ГИС MapGL для отображения карты;
- ключ 2ГИС Places API для поиска площадок;
- публичный HTTPS-адрес Mini App.

Секретные значения хранятся только в `.env`. Этот файл не добавляется в Git.

## 6. Переменные окружения

Настройки приложения хранятся в файле `.env`. Пример конфигурации находится
в `.env.example`.

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Токен для подключения к MAX Bot API |
| `MAX_BOT_USERNAME` | Публичное имя MAX-бота без символа `@` |
| `MINI_APP_URL` | Публичный адрес Mini App |
| `BACKEND_API_URL` | Адрес REST API для внутренних запросов |
| `TWOGIS_MAPGL_API_KEY` | Ключ для отображения карты 2ГИС |
| `TWOGIS_PLACES_API_KEY` | Серверный ключ для поиска спортивных площадок |
| `TWOGIS_MAP_STYLE_ID` | Идентификатор пользовательского стиля карты |
| `TWOGIS_MOSCOW_CITY_ID` | Идентификатор Москвы в 2ГИС |
| `APP_TIMEZONE` | Часовой пояс для событий и уведомлений |
| `REMINDER_POLL_SECONDS` | Интервал проверки событий для отправки напоминаний |
| `ALLOWED_ORIGINS` | Список адресов, которым разрешён доступ к REST API |
| `DATABASE_PATH` | Путь к файлу базы данных SQLite |
| `LOG_LEVEL` | Уровень логирования приложения |
| `NODE_EXTRA_CA_CERTS` | Путь к сертификату для подключения Node.js к MAX |
| `MAX_CA_CERT_PATH` | Путь к сертификату для подключения Python к MAX |

Обязательными для полного пользовательского сценария являются `BOT_TOKEN`,
`MAX_BOT_USERNAME`, `MINI_APP_URL`, `TWOGIS_MAPGL_API_KEY` и
`TWOGIS_PLACES_API_KEY`.

## 7. Используемые порты

## 9. Внешние сервисы и интеграции

### MAX

MAX используется для работы чат-бота, запуска Mini App и доставки уведомлений.
Бот получает команды через Long Polling, а backend отправляет сообщения через
MAX Bot API. MAX WebApp Bridge передаёт Mini App сведения о пользователе и
параметры запуска.

Для проверки необходимы действующий MAX-бот, корректный `BOT_TOKEN`, публичное
имя бота и доступный по HTTPS адрес Mini App. Платформа MAX является внешним
сервисом и не запускается внутри Docker.

### 2ГИС

2ГИС MapGL отображает карту, а 2ГИС Places API предоставляет сведения о
спортивных площадках. Для работы необходимы ключи `TWOGIS_MAPGL_API_KEY` и
`TWOGIS_PLACES_API_KEY`, а также доступ контейнера в интернет.

Сервисы 2ГИС являются внешними и не запускаются внутри Docker.

## 10. Работа с данными

Данные приложения хранятся в SQLite:

- спортивные события;
- участники событий;
- профили пользователей;
- ссылки на чаты событий;
- сведения об аренде площадок;
- информация об отправленных напоминаниях.

При запуске через Docker база находится в томе `unipg_data`. Данные сохраняются
после остановки и пересоздания контейнера.

Сведения о спортивных площадках запрашиваются из 2ГИС. В базе сохраняются только
данные площадки, необходимые для созданного пользователем события.

## 11. Тестовые данные

При первом запуске backend автоматически создаёт таблицы SQLite и добавляет
несколько примеров площадок с возможностью аренды.

Данные для воспроизводимой проверки REST API находятся в
`test-data/api-test-data.json`. Те же значения используются в автоматическом
сценарии `DATA-API.yaml`.

События и участники заранее не создаются. Тестовое событие нужно создать через
Mini App:

1. открыть карту;
2. выбрать спортивную площадку;
3. нажать кнопку создания события;
4. указать название, вид спорта, время и количество участников;
5. опубликовать событие.

При открытии приложения в обычном браузере используется гостевой профиль. Для
проверки уведомлений необходимо открыть Mini App из MAX, чтобы приложение
получило идентификатор пользователя MAX.

## 12. Пошаговый сценарий проверки

1. Заполнить обязательные значения в `.env`.
2. Запустить проект командой:

   ```bash
   docker compose up --build
   ```

3. Проверить состояние backend:

   ```bash
   curl http://localhost:8000/api/health
   ```

4. Открыть [http://localhost:8000](http://localhost:8000) и убедиться, что карта
   и список площадок загружаются.
5. Выбрать площадку и создать событие с будущим временем начала.
6. Открыть рабочую версию через MAX-бота и проверить получение уведомления о
   создании события.
7. Со второго аккаунта MAX присоединиться к событию. Участник должен получить
   подтверждение, а организатор — уведомление о новом участнике.
8. Для проверки напоминания создать событие, которое начнётся менее чем через
   час. Уведомление должно прийти текущим участникам один раз.
9. Нажать в уведомлении кнопку «Отказаться», открыть событие на карте и отменить
   участие. Участник и организатор должны получить уведомления об отказе.

## 13. Ожидаемое поведение

| Действие | Ожидаемый результат |
|---|---|
| Запуск приложения | Mini App и REST API доступны на порту `8000` |
| Открытие карты | Отображаются спортивные площадки Москвы |
| Создание события | Событие появляется на карте, автор получает уведомление |
| Запись на событие | Счётчик участников увеличивается, участник и организатор получают уведомления |
| Повторная запись | Счётчик участников повторно не увеличивается |
| Напоминание | Каждый текущий участник получает одно сообщение примерно за час до начала |
| Отказ от участия | Счётчик уменьшается, участник и организатор получают уведомления |
| Повторный отказ | Backend сообщает, что пользователь уже не участвует в событии |
| Перезапуск контейнера | События и участники сохраняются в SQLite volume |

## 14. Известные ограничения

- поиск площадок ограничен территорией Москвы;
- для карты требуется доступ к внешним сервисам 2ГИС;
- полный сценарий Mini App в MAX требует публичный HTTPS-адрес;
- уведомления не отправляются гостевым пользователям, открывшим приложение в
  обычном браузере;
- чат события не создаётся автоматически: организатор добавляет ссылку вручную;
- SQLite рассчитана на один экземпляр приложения и подходит для текущей MVP-версии;
- напоминания отправляются только во время работы backend;
- данные MAX WebApp Bridge в текущей версии не проходят серверную проверку подписи.

## 15. Остановка и повторный запуск

Для остановки контейнера выполните:

```bash
docker compose down
```

Команда не удаляет том `unipg_data`, поэтому данные SQLite сохраняются.

Для повторного запуска выполните:

```bash
docker compose up -d --build
```

Проверить состояние контейнера и последние сообщения журнала можно командами:

```bash
docker compose ps
docker compose logs --tail=100 web
```

проверки пользовательского сценария внутри MAX используются обычные аккаунты MAX,
открывшие Mini App через бота.
